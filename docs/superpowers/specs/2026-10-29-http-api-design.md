# HTTP API генератора (2026-10-29)

## Задача

Дать автотестам и другим системам доступ к генератору без браузера: собрать пакет по сценарию,
проверить, положить в IN/OUT стенда, забрать из OUT, ответить на входящий, управлять маршрутами.
Описание — OpenAPI 3.0 и docs/API.md на русском.

## Решения

- Версионированный префикс `/api/v1`. Старые адреса `/api/*` остаются внутренними для страницы
  интерфейса и могут меняться; на `/api/v1` держится совместимость.
- Логика не дублируется: модуль `medogen_core/api.py` (класс `Api`) — тонкий слой REST поверх
  `webui.App`. Таблица маршрутов `ROUTES` — единственный источник адресов, тест сверяет её с
  `medogen_core/openapi.json`, чтобы описание не расходилось с кодом.
- Два способа запуска:
  - `python medogen.py ui` — интерфейс и API на одном порту, без ключа (та же модель доверия, что у
    интерфейса);
  - `python medogen.py api [--host] [--port] [--token]` — только API (без страницы и внутренних
    `/api/*`), ключ необязателен (`--token` или переменная `MEDOGEN_API_TOKEN`), передаётся в
    `Authorization: Bearer …` или `X-Api-Key`. Фоновая маршрутизация работает так же, как в `ui`.
- Только стандартная библиотека Python (как и весь интерфейс).
- Идентификатор пакета — путь относительно `out/ui`, как в интерфейсе (`20261029-…_01_3.0_document_ДЭВ`,
  `_incoming/…`). В адресе его лучше кодировать целиком (`/` → `%2F`), но незакодированный
  `_incoming/x` тоже принимается.
- Ошибки: JSON `{"error": "текст"}` и код: 400 — неверный запрос, 401 — нет ключа, 404 — не найдено,
  405 — метод не поддерживается, 422 — сценарий не собрался, 500 — сбой.
- Двоичные данные (zip входящего пакета, zip для проверки) передаются телом запроса как есть
  (`application/zip`), без multipart.

## Адреса

| Метод | Адрес | Что делает |
|---|---|---|
| GET | /health | версия API, наличие lxml, форматы |
| GET | /meta | справочники: типы, виды, причины, события… |
| GET | /examples | примеры сценариев |
| GET | /stands | стенды |
| GET | /stands/{stand} | организации и папки обмена стенда |
| POST | /stands/{stand}/check | доступ к папкам OUT/архив/IN |
| GET | /stands/{stand}/out | пакеты в OUT стенда |
| POST | /stands/{stand}/out/take | забрать пакет из OUT во входящие |
| GET | /gas | поиск в справочнике ГАС |
| GET | /packages | список пакетов (фильтры type, format, incoming, limit) |
| POST | /packages | собрать по сценарию или примеру, по желанию сразу положить в IN/OUT |
| GET | /packages/{id} | карточка с результатом проверки |
| DELETE | /packages/{id} | удалить |
| GET | /packages/{id}/archive | zip пакета |
| GET | /packages/{id}/files/{name} | файл пакета (entry — файл внутри zip) |
| POST | /packages/{id}/validate | проверить |
| POST | /packages/{id}/put | положить в IN/OUT стенда |
| POST | /incoming | загрузить входящий пакет (zip) для ответа |
| POST | /validate | проверить присланный zip, ничего не сохраняя |
| GET | /routes | маршруты и их состояние |
| GET | /routes/journal | журнал пересылок |
| POST | /routes/{stand}/run | переслать сейчас (все или выбранные) |
| GET | /openapi.json | это описание |

Ответ на входящий: `POST /incoming` → `id`, затем `POST /packages` со сценарием
`{"type": "receipt", "reply_to": "ui:<id>"}`.

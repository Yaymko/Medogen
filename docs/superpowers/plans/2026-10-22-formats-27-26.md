# Пакеты МЭДО 2.7 и 2.6 (и ниже): план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** собирать, проверять и читать пакеты МЭДО 2.7 и 2.6 (и версий ниже по структуре 2.6), отвечать на них в том же формате.

**Architecture:** формат сценария сводится к «семейству» (`3.0`, `2.7.1`, `2.7`, `2.6`). Функции сообщения 2.7.1 (`message`, `notification`, `acknowledgment`) получают параметры пространства имён и версии и переиспользуются; новый `v27.py` строит паспорт ТК 2.7, новый `v26.py` строит `document.xml` и файлы письма. Проверка и чтение входящих расширяются по пространствам имён 2.7.

**Tech Stack:** Python 3.8+ (только стандартная библиотека; lxml — необязательно, для XSD), unittest, ванильный JS; Playwright для ручной проверки интерфейса.

**Spec:** `docs/superpowers/specs/2026-10-22-formats-27-26-design.md`

## Global Constraints

- Пространство имён сообщения 2.7/2.6: `http://www.infpres.com/IEDMS`; паспорта ТК 2.7: `http://minsvyaz.ru/container`, `version="1.0"`.
- `format`: `"2.7"`; `"2.6"`; `"2.N"` при N от 0 до 5 — структура 2.6, `version` = указанное значение. Прочее — прежняя ошибка с перечнем допустимых.
- Заголовки: 2.7 документ — `Транспортный контейнер`; 2.6 документ — `Документ`; квитанция — `Квитанция`; уведомление — `Уведомление`.
- 2.6: файл сообщения `document.xml`; 2.7: `message.xml` + `container.edc.zip`.
- Имена в ТК 2.7 по эталону: `<base>.pdf`, `<base>_<n>_SigStamp.sig`, `<base>_<n>_SigStamp.png`, `<base>_RegStamp.png`, приложения `<base>_att<i>.<ext>` и `<base>_att<i>.sig`; `<base>` — `document`.
- `sign_files` (только 2.6) по умолчанию `false`.
- Ошибки: «поручения и ТК ГосЭДО есть только в 2.7.1 и 3.0»; «уведомления „Поставлен на контроль“ нет в схеме 2.7/2.6»; `notify_sent` в 2.7/2.6 — предупреждение «в 2.7/2.6 уведомление нельзя приложить к ТК, notify_sent пропущен».
- Эталоны в репозиторий не кладутся; тест на эталонах читает `MEDO_REF_DIR` и пропускается без неё.
- Поведение 2.7.1 и 3.0 не меняется: все старые тесты и `build examples` проходят.

## Review Focus

1. Входящий 2.6 от СЭД с файлами, у которых кириллические имена или пробелы (`7409.docx` в эталоне, но бывают «Письмо.docx»), — читается и проверяется. Тест в Task 1 (`test_26_cyrillic_file_name`).
2. Входящий 2.7/2.6 без `deliveryIndex` (в схеме 2.7 он необязателен) — читается, получатели пустые, ответ собирается по `to` из сценария без падения. Тест в Task 1 (`test_read_without_delivery_index`).
3. Ответный документ на входящий 2.6: реквизиты (УУИД, номер, дата, организация) берутся из `document`, связь `links` строится. Тест в Task 4 (`test_reply_document_to_26_links`).
4. Причина отказа строкой, уже совпадающей с текстом перечисления 2.7 (`"Нет подписи"`), принимается без кода. Тест в Task 2 (`test_refusal_reason_text_passthrough`).
5. В интерфейсе переключение 2.7.1 → 2.6 при выбранном поручении сбрасывает вид на «документ», а не отправляет недопустимый сценарий. Проверка Playwright в Task 4.

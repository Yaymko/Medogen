# Инструкция пользователя medogen

medogen собирает тестовые пакеты МЭДО форматов 3.0, 2.7.1, 2.7 и 2.6 (и ниже). С его помощью проверяют, как СЭД
принимает входящие пакеты и отвечает на них. В каждом пакете есть envelope.ini, message.xml и
транспортный контейнер (*.edc.zip). После сборки пакет сразу проверяется по XSD и на
обязательные реквизиты.

Работать можно в браузере (интерфейс для тестировщиков) или из командной строки (сценарии JSON).
Справочник по всем полям сценариев и форматам приведён в [README](../README.md).
Пошаговый сквозной тест «исходящий из СЭД → ответы в IN» — в [инструкции для тестировщика](TESTER_GUIDE.md).

## 1. Запуск

**На своём компьютере.** Нужен Python 3.8 или новее. Откройте папку medogen и запустите
`run_ui.bat` или выполните команду:

```
python medogen.py ui
```

Браузер откроется на http://localhost:8765. Чтобы остановить сервер, нажмите Ctrl+C в окне
консоли.

**На общем сервере.** Откройте адрес, который дал администратор, например
`http://medogen.corp.local`. Устанавливать ничего не нужно. Как развернуть сервер, описано в
[DEPLOY.md](DEPLOY.md).

Для проверки по XSD нужен пакет lxml (`pip install lxml`). Без него пакеты собираются, но
схемы не проверяются, о чём интерфейс предупреждает в шапке.

## 2. Стенд и справочники

В шапке выбирается **стенд**: набор организаций с GUID и адресами МЭДО. GUID на разных стендах
различаются, поэтому для каждого тестового контура заводится свой стенд (вкладка «Организации»
→ «Новый стенд»).
Устаревший стенд удаляется кнопкой «Удалить стенд» на вкладке «Организации». Файл стенда не
стирается, а переносится в `orgs\_deleted`: чтобы вернуть стенд, переложите файл обратно в `orgs`
и уберите из имени добавленное время. Стенд-пример `default.json` не удаляется.

**Справочник ГАС ГосЭДО** содержит всех абонентов МЭДО (около 36 тысяч). Так берутся
реальные адреса и GUID, которые сверяет проверочный бот МЭДО. Чтобы загрузить справочник:

1. Откройте в браузере https://gosedo.ru/wp-content/uploads/files/addresseesActual.html и сохраните
   страницу (Ctrl+S, «Веб-страница полностью» или «только HTML»).
2. Вкладка «Организации» → «Справочник ГАС ГосЭДО» → «Загрузить» → выберите сохранённый файл.

Справочник обновляют раз в месяц или когда бот сообщает, что адреса нет в ГАС
(показатели 1.3 и 1.8).

## 3. Собрать пакет

Вкладка **«Создать пакет»**:

1. Выберите формат (3.0, 2.7.1, 2.7 или «2.6 и ниже») и тип пакета: исходящий документ, ТК ГосЭДО, обращение
   гражданина, квитанция, уведомление, цифровое поручение.
2. Выберите отправителя и получателей. Их можно взять из стенда или найти в ГАС через поле
   поиска под списком: по названию, адресу МЭДО или GUID.
3. Заполните поля документа. Обязательные поля отмечены звёздочкой (*). Поля с подсказкой
   «авто» можно оставить пустыми: номер, дату и ФИО по умолчанию подставит генератор.
   Регистрационный номер по умолчанию каждый раз новый, например MG-2110-171018-1.
4. Нажмите «Собрать пакет». Если обязательное поле не заполнено, пакет не соберётся: поле
   подсветится красным, а над кнопкой появится список. Щелчок по строке списка ведёт к полю.

Справа появится результат: GUID сообщения и документа (копируются по щелчку), состав пакета
с просмотром любого файла и результат проверки. Ниже кнопки:

- **Скачать .zip** — пакет одним архивом, его загружают в СЭД или в проверочный бот МЭДО;
- **Ответный документ, Квитанция, Уведомление, Событие по поручению** — ответ на этот пакет:
  форма заполняется сама, отправитель и получатель меняются местами.

«Очистить форму» сбрасывает и форму, и блок результата.

**Цифровое поручение.** У каждого пункта есть номер, срок, текст, исполнитель и
соисполнители. Исполнителя и соисполнителей можно найти в ГАС через поля под списками. Если
поле «Получатели» пустое, получатели берутся из исполнителей и соисполнителей пунктов.

**Форматы 2.7 и 2.6 и ниже.** Это старые форматы, которые ещё встречаются у участников.

- **2.7** — сообщение message.xml и транспортный контейнер (ТК версии 2.7, с подписью ТК) с файлами
  document.pdf, document_1_SigStamp.sig и т.д., как в эталоне «2.7. Входящее письмо».
- **2.6 и ниже** — без контейнера: document.xml с реквизитами документа и списком файлов, сами
  файлы лежат рядом. В списке версии рядом с форматом можно выбрать 2.6, 2.5, 2.4 … 2.0: пакет собирается
  по структуре 2.6, меняется только номер версии. Флажок **«Файлы подписей»** добавляет к
  каждому файлу подпись .sig (в эталонах 2.6 подписей нет, поэтому по умолчанию выключен).
- В обоих форматах нет поручений и ТК ГосЭДО: при выборе 2.7 или 2.6 вид «Поручение»
  недоступен, а заполненное поручение переключается на «Документ».
- В квитанции об отказе нет кода ошибки, только комментарий. У уведомления «Отказано в
  регистрации» одна причина из перечня схемы; уведомления «Поставлен на контроль» нет.

## 4. Входящий пакет из СЭД и ответы пачкой

Вкладка **«Пакеты»** → загрузите пакет из СЭД: .zip, файлы (envelope.ini, message.xml,
*.edc.zip; для 2.6 — document.xml и файлы документа) или папку. Формат (3.0, 2.7.1, 2.7, 2.6 и
ниже) определяется сам, ответы собираются в том же формате и той же версии. Можно просто перетащить их в окно.

1. Пакет проверяется: XSD, обязательные реквизиты, формат UUID и дат. Если загружен полный
   справочник ГАС, адреса и GUID сверяются с ним так же, как это делает бот. Расхождения с ГАС
   показаны отдельным блоком «Сверка с ГАС».
2. Откроется окно **«Ответы пачкой»**. Отметьте нужные ответы: квитанции о приёме или отказе,
   уведомления, ответный документ. Затем нажмите «Сформировать ответы». Каждый ответ
   собирается отдельным пакетом, все их можно скачать одним архивом.
3. Ответ помнит пакет, на основании которого собран. В списке «Собранные и входящие пакеты»
   колонка «Основание» ведёт к основному пакету, а у основного пакета там написано, сколько у
   него ответов. В карточке пакета блок «Связанные пакеты» перечисляет основание и все ответы
   (с отметкой «в IN»), по ним можно переходить. Поиск по имени основного пакета показывает его
   вместе с ответами. Связи есть у пакетов, собранных после этого обновления; у старых квитанций
   основание находится по GUID сообщения.

## 5. Обмен с СЭД через папки OUT и IN

Если СЭД тестового контура выкладывает исходящие пакеты в общую папку OUT и забирает входящие из
папки IN, medogen может работать вместо транспорта МЭДО.

**Настройка (один раз на стенд).** Вкладка «Организации» → блок «Обмен с СЭД»:

- **OUT** — папка, куда СЭД кладёт исходящие пакеты, например `\\srv-sed\MEDO\OUT`;
- **OUTArchiveGen** — куда переносятся забранные пакеты. Если поле пустое, это папка `OUTArchiveGen`
  рядом с OUT;
- **IN** — папка, из которой СЭД забирает входящие.

Нажмите «Проверить доступ». medogen читает OUT и пишет пробный файл в OUTArchiveGen и IN, у каждой
папки должно быть «доступна». Доступ проверяется для учётной записи, под которой запущен
medogen (на общем сервере это учётная запись службы, а не ваша).

**Работа.**

1. Вкладка «Пакеты», блок «Папка OUT»: список пакетов, которые отправила СЭД. «Обновить»
   перечитывает папку. Блок сворачивается щелчком по заголовку (это запоминается в браузере).
   Слева оглавление: переход к папке OUT, к списку «Собранные и входящие пакеты», к открытому
   пакету и наверх, с числом пакетов в OUT и в списке.
2. «Забрать» копирует пакет в medogen, переносит его папку из OUT в OUTArchiveGen и открывает
   «Ответы пачкой».
3. Отметьте ответы, в поле «Пакеты без ошибок сразу положить» выберите «в IN» (или «в OUT»),
   затем «Сформировать ответы». В таблице результата у каждого ответа отметка «в IN» или «в OUT».
4. Любой собранный пакет можно положить в IN или в OUT и позже: кнопки «Положить в IN» и
   «Положить в OUT» в карточке пакета. В карточке видно, когда и куда пакет был положен.
   Пакет в OUT выглядит так, будто его отправила СЭД этого стенда: он появляется в блоке
   «Папка OUT», его можно «Забрать», а если у стенда включена автоматическая маршрутизация,
   он уйдёт в IN второго стенда (раздел 6).
5. В списке «Собранные и входящие пакеты» колонка «Забран со стенда» показывает, из OUT какого
   стенда взят пакет. У пакетов, собранных в medogen, она пустая.

Что важно знать:

- В IN и OUT попадают только пакеты без ошибок проверки. Пакет пишется во временную папку
  `.<имя>.medogen-tmp` и потом переименовывается, поэтому СЭД не увидит его недописанным.
- Имя папки в IN (OUT) такое же, как у пакета в medogen. Если папка с таким именем там ещё
  лежит (её не забрали), повторно пакет не кладётся.
- Из командной строки: `python medogen.py build сценарий.json --orgs orgs\стенд.json --put out`
  собирает и сразу кладёт пакеты в OUT (`--put in` — в IN), а
  `python medogen.py put <папка пакета> --orgs orgs\стенд.json --to out` кладёт уже собранный пакет.
- Пакет из OUT не удаляется, а переносится в OUTArchiveGen. Если имя там занято, добавляется
  `_1`, `_2`. Чтобы повторить тест, верните папку из OUTArchiveGen в OUT.

## 6. Маршрутизация между стендами

medogen может работать транспортом МЭДО между двумя тестовыми СЭД: забирать пакеты из OUT
одного стенда, проверять их и класть в IN другого. Ответы второй СЭД (квитанции, уведомления,
ответный документ) идут обратным маршрутом.

**Настройка.** На вкладке «Организации», в блоке «Обмен с СЭД»:

1. Выберите стенд 1, укажите его OUT и IN, в поле «Пересылать в стенд» выберите стенд 2,
   поставьте галочку «Автоматически» и нажмите «Сохранить».
2. Выберите стенд 2 и сделайте то же самое, указав в «Пересылать в стенд» стенд 1. Это
   обратный путь для ответов.

**Что происходит с пакетом.** Каждые 10 секунд medogen смотрит OUT стендов с галочкой:

- новый пакет берётся, когда его файлы (состав, размеры, время изменения) не поменялись между двумя
  проходами подряд, то есть через 10–20 секунд: так medogen не схватит пакет, который СЭД ещё пишет.
  Часы сервера СЭД на это не влияют. «Переслать сейчас» само ждёт 5 секунд и проверяет пакет ещё раз;
- дописанный пакет забирается как кнопкой «Забрать»: копия во входящие medogen, оригинал в OUTArchiveGen.
  Если перенести оригинал в OUTArchiveGen не удалось (нет прав на удаление в OUT), пакет не
  пересылается, чтобы СЭД не получала его на каждом проходе: в журнале «не забран» с причиной.
  Исправьте права и нажмите «Переслать сейчас»;
- пакет проверяется так же, как собранные (XSD, состав, обязательные реквизиты). Без ошибок он
  кладётся в IN второго стенда под тем же именем папки. Предупреждения ГАС пересылке не мешают;
- пакет с ошибками в IN не кладётся и остаётся во входящих с отчётом проверки.

**Блок «Маршрутизация»** на вкладке «Пакеты» показывает маршруты (режим, последний проход,
ошибку доступа, счётчики с запуска) и журнал пересылок: время, маршрут, пакет, формат и результат
(«в IN», «ошибки проверки», «ошибка записи», «не забран»). По имени пакета он открывается справа.
«Переслать сейчас» запускает проход сразу, в том числе для маршрута без галочки.

**Выборочная пересылка.** Если у маршрута снята галочка «Автоматически», в блоке «Папка OUT» у
каждого пакета есть галочка (в заголовке — «выбрать все») и кнопка «Переслать выбранные в стенд …».
Выбранные пакеты проходят тот же путь: проверка, IN второго стенда, оригинал в OUTArchiveGen,
строка в журнале. Остальные остаются в OUT. С включённой автоматикой выбирать нечего: маршрутизатор
сам забирает всё из OUT, поэтому вместо галочек показывается подсказка.
«Переслать без проверки» кладёт в IN пакет с ошибками или пакет, который не удалось записать
(например, в IN была папка с тем же именем).

Что важно знать:

- Опрос работает, пока запущен интерфейс (или служба). Интервал меняется ключом
  `python medogen.py ui --route-interval 30`, `0` выключает опрос (останется «Переслать сейчас»).
- На стенде с галочкой «Автоматически» всё из OUT забирает маршрутизатор, поэтому ручное
  «Забрать → Ответы пачкой» там не понадобится.
- Журнал хранится в `out/ui/_routing/journal.jsonl`.

## 7. Проверочный бот МЭДО

Собранный пакет (.zip) можно проверить в «Валидаторе сообщений МЭДО». Если бот нашёл
ошибку, сохраните отчёт (validation-report.html) и передайте его вместе с пакетом
разработчику. Каждую ошибку бота закрепляют тестом в `tests/test_bot_findings.py`.

## 8. Командная строка

```
python medogen.py build examples                  собрать все примеры
python medogen.py build мой_сценарий.json --zip   собрать свой сценарий и упаковать в .zip
python medogen.py validate <папка пакета>         проверить любой пакет, в том числе из СЭД
python medogen.py gas Тюменская область           поиск в справочнике ГАС
python -m unittest discover -s tests -v           автотесты (или run_tests.bat)
```

Любой пакет, собранный в интерфейсе, можно выгрузить кнопкой «Показать JSON сценария». Этот
сценарий соберёт такой же пакет из командной строки.

## 9. Где лежат файлы

| Что | Где |
|---|---|
| Пакеты из интерфейса | `out/ui/<дата-время>_<тип>` |
| Входящие пакеты, загруженные в интерфейс | `out/ui/_incoming` |
| GUID и номера собранных пакетов | `out/ui/_manifests/*.json` |
| Стенды (организации и папки обмена с СЭД) | `orgs/*.json` |
| Пакеты, забранные из OUT | `out/ui/_incoming` (оригинал в OUTArchiveGen сервера СЭД) |
| Журнал маршрутизации между стендами | `out/ui/_routing/journal.jsonl` |
| Справочник ГАС | `gas/gas.json` |

## 10. Ограничения

- Подписи (.p7s и XMLDSig в digital.xml) делаются встроенным тестовым сертификатом «MEDOGEN
  TEST SIGNER». По формату они корректны, но СЭД, которая проверяет доверие к сертификату,
  их отклонит. Подписывать .p7s настоящим ключом КриптоПро можно в сценариях командной строки
  через `settings.sign_command` (см. README, раздел «Подписи»).
- Генерируются форматы 3.0, 2.7.1, 2.7 и 2.6 (версии 2.0–2.5 — по структуре 2.6).
- Принятые допущения перечислены в README, раздел «Допущения».
